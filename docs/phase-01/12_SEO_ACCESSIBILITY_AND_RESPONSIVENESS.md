### Part 1: Search Engine Optimization (SEO) & Rendering Architecture

#### 1.1 Hybrid Semantic Pre-Rendering & Client Mounting Architecture
The public website operates on a **hybrid PHP edge pre-rendering and React createRoot mounting architecture** to ensure complete, instant search engine indexability on Hostinger shared hosting without requiring a Node.js SSR daemon.

```mermaid
sequenceDiagram
    autonumber
    actor Crawler as Googlebot / Bingbot / Social Scraper
    actor Browser as Modern Desktop / Mobile Browser
    participant Apache as Hostinger Apache (.htaccess)
    participant PHP as PHP SEO Front Controller (index.php)
    participant DB as MySQL Database
    participant React as React Client Bundle (createRoot Mounting)

    Crawler->>Apache: GET /services/clinical-workforce-solutions
    Apache->>PHP: Rewrite non-file request to index.php
    PHP->>DB: Query service by slug
    DB-->>PHP: Service Record (title, summary, markdown)
    PHP-->>Crawler: HTTP 200 OK with escaped meta, JSON-LD, and full semantic HTML in #ssr-fallback
    Note over Crawler: Complete text content indexed immediately without JS execution.

    Browser->>Apache: GET /services/clinical-workforce-solutions
    Apache->>PHP: Rewrite to index.php
    PHP-->>Browser: HTTP 200 OK with HTML + React Scripts
    Browser->>React: Execute bundle; createRoot client mounting
    React->>Browser: React mounts into #root; #ssr-fallback hidden; client-side routing active
```

#### 1.2 Critical Architectural Distinction: Pre-Rendering vs. Hydration
To eliminate technical ambiguity, the platform distinguishes between three rendering paradigms:
1. **PHP-Rendered Semantic Fallback (`#ssr-fallback`):** The PHP front controller (`index.php`) queries MySQL directly, escapes all strings, and generates an accessible HTML markup container (`<div id="ssr-fallback">`) containing complete semantic typography (`<h1>`, `<h2>`, `<p>`, `<ul>`, `<article>`). This markup is served immediately to crawlers and users with JavaScript disabled.
2. **React Client-Side Mounting (`createRoot`):** In modern browsers with JavaScript active, the compiled React bundle executes and mounts via `createRoot(document.getElementById('root'))`. Upon successful mount, React takes over interactivity and cleanly removes or hides `#ssr-fallback` (`display: none` / unmount), preventing duplicate content or visual flashes (CLS < 0.05).
3. **Why this is NOT React `hydrateRoot`:** True React hydration (`hydrateRoot`) requires a Node.js server runtime that renders matching React component virtual DOM trees on the server. Because the production environment is Hostinger PHP/HTML shared hosting without a persistent Node.js daemon, `createRoot` client mounting is used. Content equivalence is maintained by ensuring that the PHP SQL queries and React API calls render identical primary text copy.

#### 1.3 Functional SEO Requirements:
1. **Meaningful HTML Without JavaScript:**  
   When JavaScript is disabled (`<noscript>` or curl request), the page output contains complete semantic typography rendering identical core copy to the client-rendered application.
2. **True HTTP Status Headers:**  
   - Valid public routes emit authentic `HTTP/1.1 200 OK`.
   - Invalid, unpublished, or non-existent slugs emit authentic `HTTP/1.1 404 Not Found` (strictly eliminating soft-404 search penalties).
   - Historical renamed slugs emit authentic `HTTP/1.1 301 Moved Permanently` with `Location` header.
3. **Dynamic XML Sitemap (`/sitemap.xml`):**  
   Dynamically generated by `src/Controllers/SitemapController.php` (cached via file TTL 3600s, invalidated upon content publish/unpublish):
   - Includes all published static pages, active service pillars, active industry verticals, and published articles.
   - Outputs valid W3C XML with `<loc>`, `<lastmod>`, and `<changefreq>`.
4. **Structured Data (JSON-LD) Schemas:**  
   Injected into `<head>` per page type:
   - Homepage: `Schema.org/Organization` + `MedicalBusiness` (B2B non-clinical profile).
   - Service Pages: `Schema.org/Service` with `provider`, `serviceType`, `areaServed`.
   - Industry Pages: `Schema.org/CollectionPage`.
   - Articles: `Schema.org/Article` with `headline`, `author`, `datePublished`, `image`.
   - FAQs: `Schema.org/FAQPage` with `mainEntity` array of questions and answers.
   - Careers: `Schema.org/JobPosting` with `title`, `hiringOrganization`, `jobLocation`, `validThrough`.
5. **OpenGraph & Twitter Social Cards:**  
   Every public route outputs `<meta property="og:title">`, `<meta property="og:description">`, `<meta property="og:image">`, `<meta property="og:url">`, and `<meta name="twitter:card" content="summary_large_image">`.
6. **No Rankings Guarantees:**  
   The system provides optimal technical crawlability and semantic structure; search ranking positions and crawler visitation schedules depend on external search engine algorithms and are not guaranteed prior to empirical testing.

#### 2.2 Keyboard Navigation & Focus Ring Standards:
1. **Visible Focus Rings:** All interactive elements (`<button>`, `<a>`, `<input>`, `<select>`, `<textarea>`) display an unambiguous, high-visibility focus ring when navigated via keyboard: `outline: 2px solid #665CE9; outline-offset: 2px;`.
2. **Logical Tab Sequence:** Tab sequence strictly follows visual reading order (left-to-right, top-to-bottom); `tabindex > 0` is strictly prohibited.
3. **Skip to Content Link:** Primary navigation includes an accessible skip-link:
   ```html
   <a href="#main-content" class="sr-only focus:not-sr-only focus:absolute focus:top-4 focus:left-4 focus:z-50 focus:p-4 focus:bg-[#665CE9] focus:text-white focus:rounded-lg">
     Skip to main content
   </a>
   ```
4. **Modal Focus Trapping:** When any modal or dialog opens (Leadership bios, Mobile navigation drawer, Confirmation dialogs), focus is trapped within the container; pressing `Escape` dismisses the modal and returns focus to the triggering element.
5. **Reduced Motion Query (`prefers-reduced-motion`):**
   ```css
   @media (prefers-reduced-motion: reduce) {
     *, ::before, ::after {
       animation-duration: 0.01ms !important;
       animation-iteration-count: 1 !important;
       transition-duration: 0.01ms !important;
       scroll-behavior: auto !important;
     }
   }
   ```

#### 2.3 Screen Reader & ARIA Standards:
- All form inputs explicitly linked to labels via `<label for="field-id">`.
- Validation errors linked via `aria-describedby="field-error-id"` and flagged with `aria-invalid="true"`.
- Asynchronous form status announcements use `aria-live="polite"` or `role="status"`.
- Accordions implement `aria-expanded="true|false"` and `aria-controls="accordion-panel-id"`.

### Part 3: Responsive Viewport Architecture & Breakpoints

The application enforces a fluid, mobile-first responsive layout utilizing Tailwind CSS standard breakpoint tokens:

```
Breakpoint Hierarchy:
┌─────────────────┬───────────────────┬────────────────────────────────────────┐
│ Breakpoint      │ Viewport Width    │ Target Device Classes                  │
├─────────────────┼───────────────────┼────────────────────────────────────────┤
│ Mobile (Base)   │ < 640px           │ Smartphones (iPhone SE, 13, Galaxy)    │
│ Small (sm)      │ 640px – 767px     │ Large Phones / Phablets                │
│ Medium (md)     │ 768px – 1023px    │ Tablets (iPad, Galaxy Tab, Portrait)   │
│ Large (lg)      │ 1024px – 1279px   │ Small Laptops / Tablets (Landscape)    │
│ Extra Large (xl)│ >= 1280px         │ Desktop Monitors / Large Laptops       │
```
