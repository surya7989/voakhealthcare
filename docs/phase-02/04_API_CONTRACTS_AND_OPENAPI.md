## 1. REST Architectural Standards & Protocols

The Voak Health Care API is a versioned, RESTful, JSON-over-HTTPS communication protocol designed to support public website capabilities and secure administrative console workflows.

### 1.1 Base Path Routing & Versioning Standard
- **API Gateway Entry Point:** `public_html/api/index.php`.
- **Canonical API Base Path:** `/api/v1`.
- **Public Domain Endpoints:** `/api/v1/public/*` (accessible anonymously, rate-limited, read-only or bot-protected form submissions).
- **Protected Admin Endpoints:** `/api/v1/admin/*` (strictly protected by session authentication cookie `Path=/api/v1/admin`, CSRF token, and RBAC permission evaluation).

### 1.2 Uniform Response Envelope Architecture
All responses adhere to a deterministic JSON envelope contract:

#### Successful Mutation or Resource Retrieval:
```json
{
  "success": true,
  "data": { ... },
  "meta": {
    "timestamp": "2026-10-16T09:00:00Z",
    "correlation_id": "req_6711a3b8c9d0e"
  }
}
```

#### Paginated Collection Retrieval:
```json
{
  "success": true,
  "data": [ ... ],
  "pagination": {
    "total_records": 124,
    "current_page": 1,
    "per_page": 20,
    "total_pages": 7,
    "has_next_page": true,
    "has_prev_page": false
  },
  "meta": {
    "timestamp": "2026-10-16T09:00:00Z",
    "correlation_id": "req_6711a3b8c9d0f"
  }
}
```

#### Standardized Error Envelope:
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "The provided entity fields failed business validation rules.",
    "reference_id": "REF-ERR-653A8B14",
    "validation_errors": {
      "contact_phone": ["Phone number must adhere to international E.164 format (+[country][digits])."]
    }
  },
  "meta": {
    "timestamp": "2026-10-16T09:00:00Z",
    "correlation_id": "req_6711a3b8c9d10"
  }
}
```

## 2. Standard HTTP Status Codes & Error Taxonomy

| HTTP Status Code | Meaning | Standard Application in Voak Platform |
| :---: | :--- | :--- |
| **200 OK** | Success | Successful GET, PUT, PATCH, or idempotent POST query. |
| **201 Created** | Created | Successful entity creation (Inquiry, Application, RFP, User). Emits `Location` header. |
| **204 No Content** | Deleted | Successful DELETE mutation where no entity body is returned. |
| **301 Moved Permanently** | Redirect | Public route redirect for renamed slugs, generated by the SEO redirect engine. |
| **400 Bad Request** | Malformed | Syntactically invalid JSON or missing mandatory HTTP headers. |
| **401 Unauthorized** | Unauthenticated | Missing, expired, or invalid session cookie on `/api/v1/admin/*`. |
| **403 Forbidden** | Unauthorized | Authenticated user lacks the required RBAC permission key, or CSRF token invalid. |
| **404 Not Found** | Missing | Non-existent entity ID or unregistered slug. Strictly authentic 404 header. |
| **409 Conflict** | Concurrency | Optimistic concurrency clash (`updated_at` mismatch) or duplicate unique key. |
| **422 Unprocessable** | Validation Failure | Entity data fails semantic validation (MIME bytes, regex, required fields). |
| **429 Too Many Requests**| Rate Limited | IP address or session exceeded rate limit thresholds. |
| **500 Server Error** | Internal Failure | Uncaught exception; sanitized error returned with correlation reference ID. |

### 4.2 Server URL & Path Prefix Contract
To prevent path duplication bugs (such as `/api/v1/api/v1/...` in generated client SDKs):
- The `servers` array defines base URLs:
  - Production: `https://voakhealthcare.com/api/v1`
  - Staging: `https://staging.voakhealthcare.com/api/v1`
- The `paths` keys in `openapi.json` are specified without redundant `/api/v1` prefixes (e.g., `/public/homepage`, `/admin/auth/login`), guaranteeing clean, standard client code generation.
